# RAPPORT — Dataset Strategy

_Document 3 of the research package. Row counts were read from the Hugging Face Hub API on 2026-11-19; licenses are the Hub-declared fields. A dataset is admitted only if both are recorded._

## 1. Decision taxonomy

RAPPORT learns six bounded decision families. They are deliberately *not* merged into one label space: the output each family consumes is different, and mixing them without a task representation is how multi-task models learn to average.

| Family | Question the model answers | Output consumed | Why it belongs |
|---|---|---|---|
| `choice` | Which of n options is correct/best? | `chosen_index`, `p_i` | The core N-way decision; supports 2–8 options |
| `preference` | Which of two (or a ranked list of) responses is preferred? | `chosen_index`, pairwise margin | Human preference is the densest source of *decision* signal per token |
| `scoring` | How good is each option on a graded scale? | `scores[]` (0–1 utility) | Teaches graded quality, not just argmax |
| `probability` | Is this proposition true? | `P`, Brier | Teaches a proper probability rather than a label |
| `abstention` | Is the question answerable from the given state? | `answerable`, `abstain` | The documented weakest behaviour of typed decision models |
| `risk` | Which harm categories does this content touch? | `risk[8]` | Safety veto; also guards over-refusal |

Excluded on purpose: sequential decision-making (no environment, no transition model), general knowledge recall as a standalone objective (MMLU is used as *choice* data, not as a knowledge target), and tool execution (only tool *selection* would be in scope, and it is deferred to v1.1).

## 3. Evaluation criteria applied to every candidate

Each source is scored on ten dimensions before admission. T07 writes the result into the acquisition manifest; T08/T10 enforce it.

`source`, `license`, `declared_rows`, `observed_rows`, `unique_after_dedup`, `label_method` (human / model / derived), `task_fit` (0–3), `contamination_risk` (does the source overlap a benchmark we report?), `storage_download_mb`, `preprocessing_cost` (0–3).

Admission rule: `license` must be a recognized SPDX id (or explicitly `unverified` and kept out of the default mixture), `task_fit ≥ 2`, and `contamination_risk` must not name a test set in `docs/evaluation.md`.

## 4. Cleaning pipeline (order matters)

```
raw → ingest-normalize → exact dedup → near dedup → contradiction audit
    → quality rules → option-count handling → label-confidence report
    → difficulty stratify → group split → leakage assert → mixture sample
```

1. **Ingest-normalize** — Unicode NFC, strip HTML tags and entities, collapse whitespace, normalize quotes. Store both the raw hash and the normalized hash.
2. **Exact dedup** — sha256 over `(task_family, goal, sorted normalized options, chosen)`. Also detect the *same* `(goal, state, options)` with a *different* `chosen`; those are contradictions, not duplicates.
3. **Near dedup** — MinHash (128 permutations, 5-gram shingles) at Jaccard ≥0.9 for options and ≥0.85 for state. `datasketch` LSH; the threshold is recorded in `SplitManifest.dedup_threshold`.
4. **Contradiction audit** — a group with two different gold labels is *reported*, not silently resolved. Default: drop the group from training, keep it in a `contested` file, and report the count. Silently picking one label is how a benchmark gets poisoned.
5. **Quality rules** (each named, each counted):
   `Q1` empty or <3-token option · `Q2` markup residue (`<br>`, `&amp;`, `**`) · `Q3` duplicate option text after normalization · `Q4` chosen index out of range · `Q5` total length >512 tokens after truncation policy · `Q6` option that is only punctuation or a placeholder (`N/A`, `none of the above` is *kept*, it is a real option).
6. **Option-count handling** — `n > 8`: keep the gold option and 7 sampled distractors (seeded, stratified by distractor plausibility where the source provides it). Record that the example was reduced. `n < 2`: drop.
7. **Label-confidence report** — run confident-learning-style out-of-fold agreement (Northcutt et al., arXiv 2103.14749) and *report* the estimated noise rate per source. Do **not** filter on it: the brief is explicit that difficult and unusual examples must not be deleted for being unusual. Filtering is limited to rules Q1–Q6, which are structural, not difficulty-based.
8. **Difficulty stratify** — score every example with the frozen-embedding cosine baseline (T18). Mark `baseline_correct` true/false. This is a cheap, model-based difficulty proxy; it costs one matrix multiply per example.
9. **Group split** — split by `group_id` (prompt/document), never by row. 70/15/15. Additionally hold out **one entire source** from training to form the OOD test.
10. **Leakage assert** — fail the build if any `group_id`, any normalized option text ≥40 tokens, or any exact 13-gram appears in two splits.

## 5. Information density: how the training set is chosen

Random sampling from ~340k available rows would waste most of the budget on near-duplicates and trivial items. Four cheap stages, each measurable:

| Stage | Rule | Expected yield | Evidence |
|---|---|---|---|
| Dedup | exact + MinHash | 340k → 210k | Dedup improves LM quality at fixed compute (arXiv 2107.06499) and SemDeDup shows large redundancy in web corpora (arXiv 2303.13506) |
| Quality | rules Q1–Q6 | 210k → 190k | Structural filters, not difficulty filters |
| Difficulty | keep 100% of `baseline_correct = false`, 45% of `baseline_correct = true` | 190k → 140k | Data pruning can match full-data training (arXiv 2206.14486); the proxy is cheap and auditable |
| Diversity | cap each source at 25% of its family, cap each 20-topic cluster at 10% | 140k → 115k | Prevent one source or one topic from dominating |

**Rejected selection methods.** Gradient-influence selection (LESS, arXiv 2402.04333) needs per-example gradients; active learning needs an oracle in the loop; synthetic generation needs quality control that costs more than it saves at this scale. Each is rejected with a reason, not a preference.

**Curriculum.** Epochs 1–2 use easy→hard ordering by the difficulty score; epochs 3+ use uniform order with hard examples oversampled 1.5×. Ablation A6 in T21 compares this against uniform ordering. If curriculum does not beat uniform by 1 point, it is dropped — it adds a moving part for no measured gain.

## 6. Final recommended mixture

Train target = 115,600 sampled rows, split across the six families below. Percentages are of the train total; the training fixture counts must reproduce within 1%.

| Family | Sources (train rows) | Share | Options per example |
|---|---|---|---|
| preference | HH-RLHF 23,000 + HelpSteer2 10,000 | 33,000 | 28.5% | 2–4 |
| choice | `cais/mmlu` auxiliary_train 30,000 (disjoint from test by construction) | 30,000 | 25.9% | 4 |
| risk | Aegis 2.0 18,000 (XSTest is evaluation-only) | 18,000 | 15.6% | 2 |
| abstention | AbstentionBench-derived 12,000 | 12,000 | 10.4% | 2–3 |
| probability | TruthfulQA 1,600 + auxiliary_train-derived binary 10,000 | 11,600 | 10.0% | 2 |
| scoring | HelpSteer2 attributes 11,000 | 11,000 | 9.5% | 2–4 |
| **Total** | | **115,600** | **100%** | |

Source reconciliation (every source stays within its declared admitted size):

- HH-RLHF 23,000 of 169,352 ✓; HelpSteer2 21,000 of 21,362 ✓ (10,000 preference + 11,000 scoring); `cais/mmlu` auxiliary_train 30,000 of >99,000 ✓ (+ 10,000 derived binary rows for probability); TruthfulQA 1,600 of 1,634 ✓; Aegis 2.0 18,000 of 33,416 ✓; AbstentionBench-derived 12,000 ✓ (per-subset conversion rates reported by T09).
- **UltraFeedback-binarized is the designated source-held-out OOD set**: it contributes zero rows to train/dev, is downloaded (~200 MB) solely to build the 8,000-row OOD evaluation, and is reported as the preference OOD reference together with RewardBench trios. Substitution rule: if its cache cannot be built, the OOD set becomes the preference rows of an independent HH-RLHF domain cluster never sampled for training, recorded in the manifest.
- ARC and HellaSwag are both absent from the train mixture (CC-BY-SA share-alike; undeclared license respectively). ARC is not required by any acceptance criterion.
- MMLU-Pro (12,102) and MMLU test (14,042) are **evaluation-only**; auxiliary_train is admitted for training precisely because it is disjoint from both by construction, and the T10 leakage assertion enforces that overlap mechanically.

Dev = 12,000 and test = 12,000, drawn proportionally and group-disjoint. OOD test = 8,000 preference rows from UltraFeedback-binarized (MIT).

**Starter subset (55,000).** choice 12,000 · preference 20,000 (HH-RLHF 16,000 + HelpSteer2 4,000) · scoring 5,000 · probability 4,600 · abstention 6,600 · risk 6,800. Total = 12,000 + 20,000 + 5,000 + 4,600 + 6,600 + 6,800 = **55,000 exactly**. Implementation must reproduce these counts (TASK-13 acceptance).

**What is essential vs optional.** Essential: HH-RLHF (real human preference), `cais/mmlu` auxiliary_train (multi-option decision volume), HelpSteer2 (graded scores), TruthfulQA (probability), Aegis 2.0 (risk), AbstentionBench (abstention). Optional and excluded by default: SHP (no declared license), ARC (share-alike), MMLU-Pro/MMLU test (evaluation only), HellaSwag (no license), UltraFeedback (withheld as the OOD set).

**Why withhold UltraFeedback.** Its pairs are AI-judged, not human; at this scale it is redundant with HH-RLHF, and withholding it preserves a clean generalization check at zero cost.

## 7. Storage budget

| Artifact | Size | Location |
|---|---|---|
| Raw downloads (only needed subsets, streamed; UltraFeedback binarized ~200 MB for OOD only) | ≤2.2 GB | `data/raw` (ephemeral) |
| Processed parquet (~140k rows) | ~215 MB | `data/processed` |
| Tokenized packed arrays (~140k × 512 int32) | ~250 MB | `data/tokenized` |
| Split manifest + fingerprints | <5 MB | `data/processed` |
| Teacher soft-label cache (115k × 8 fp16) | ~2 MB | `cache/teacher` |
| Checkpoints (keep 3) | ~400 MB | Drive |
| **Total persistent** | **≤3.1 GB** | Drive free tier is 15 GB |

The two datasets that must never be fully downloaded: UltraFeedback (20.7 GB) and SHP (9.7 GB). Only the binarized subset of the former is fetched, for evaluation. Both are streamed and reduced before they touch disk.

## 8. Unresolved questions

- **Is ARC's CC-BY-SA share-alike triggered by model weights?** Unclear and jurisdiction-dependent. It stays out of the default mixture; the plan does not depend on it.
- **Can AbstentionBench be converted to the typed schema without distorting it?** Its 20 sub-datasets have heterogeneous "unanswerable" definitions. T09's adapter must report per-subset conversion rates, and the report must not pool them into a single abstention number.
- **Is `baseline_correct` a good difficulty proxy?** It is cheap and auditable, but it correlates with the baseline's biases. Ablation A6 reports whether hard-example oversampling actually helps.
- **Does withholding UltraFeedback limit preference OOD signal?** It is one AI-judged source of moderate size; the OOD block is a *reference*, not a benchmark re-labelled as our test set, and it is reported next to RewardBench trios instead of alone.
