## Contract rulings (gaps the contract left open, decided here)
1. **Acquisition streams raw rows, not `DecisionExample`.** The adapters (TASK-09) own schema mapping; acquisition owns storage + provenance. `DecisionExample` is never imported (the "only where needed" clause — it isn't). Rows are projected via `columns=` and filtered via `row_filter=` at write time — that is the "filtered parquet shards" requirement; `observed_rows` counts post-filter rows.
2. **Top-level `sha256` = digest over the ordered shard set** (`basename`, shard hash, size), not a single file — reproducible, and independent of the (absolute) `output_dir`. Per-shard hashes live in `shard_sha256`; sizes in `shard_bytes`, both keyed by the same string as `shards` entries.
3. **`shards: list[Path]`** — the contract's `list[path]` read literally; serialized as path strings in JSON, parsed back to `Path`.
4. **Quarantine happens before any download** — an unlicensed source is recorded (manifest with `observed_rows: 0`, `shards: []`, reason) and **nothing is materialized**. Share-alike/review-flagged licenses are quarantined the same way via `quarantine_licenses=` (e.g. `cc-by-sa-4.0`). The mixture (TASK-13) consumes only `status` + `license`; this task does not reach into it.
5. **200 MB is enforced before bytes hit disk, not after**: shards are encoded in memory, the projected total is checked against `max_bytes`, and an over-cap source never exists on disk — not transiently. Refusal is a typed `CorpusTooLargeError` *and* a recorded quarantine manifest (`quarantine_reason` carries observed bytes + cap). The contract's "assert `sum(shard_bytes) <= 200 MB`" was implemented as a typed pre-write check + post-loop invariant rather than a bare `assert` (asserts vanish under `-O` and can't carry a recorded verdict); note for the record, not a deviation from behaviour.
6. **Idempotency is strict**: an existing *valid* manifest (admitted or quarantine) is returned untouched and the downloader is **never called** — verified for quarantine verdicts too (a license review re-admission path is `refresh=True`, or delete the manifest; documented in `acquire_source`'s docstring). Any hash/missing-shard/manifest inconsistency **raises** — it never triggers a silent re-download. A corrupt manifest raises `DATA_MANIFEST_INVALID`.
7. **A failed download writes NO manifest** (partial corpus deleted, `DATA_DOWNLOAD_FAILED` raised). Writing a failure manifest would make the idempotent re-run return the failure verdict forever; absence of manifest = "not acquired", which the mixture also refuses. Deliberate trade-off for operability; the refusal cases (unlicensed, over-cap) *do* write manifests because those are decisions, not accidents.
8. **Manifest filename**: `source-manifest.json` inside the per-source `output_dir` (one source per dir via the CLI). Manifest is written atomically after shard renames (commit point); a crash mid-run leaves no manifest and stale `.acquire-tmp-*` dirs are removed in `finally` on the failure path.
9. **`acquired_at`**: UTC ISO-8601 seconds; injectable `now=` for deterministic tests. Re-runs do not touch it.
10. **Statuses**: exactly `admitted | quarantine` (validated). `license_origin` records *how* the license was known (`licenses_mapping` | `hub_metadata` | `missing`) for audit; `quarantine_reason` carries the human verdict (no license / policy-quarantined / over-cap, with bytes + limit).
11. Test file named `test_source_manifest.py` because `tests/unit/config/test_manifest.py` (TASK-01's glob, untouched) already owns the `test_manifest` basename — pytest import-mismatch otherwise. `src/data/__init__.py` NOT created (not in my glob; PEP 420 namespace, mirrors core).
