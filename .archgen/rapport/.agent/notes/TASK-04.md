## Rulings (gaps the contract left open)
1. **Stand-in tokenizer, not bge-small.** No pretrained vocab ships offline. `RapportTokenizer` is a deterministic, dependency-free, word-piece-ish stand-in: printed-ASCII chars as bare + `##` continuation pieces, a fixed set of multi-char digraph/suffix pieces, one whitespace char = one `Ġ` piece, control tokens `[PAD]=0`, `[UNK]=1`, specials 2–6, 257 total, sorted vocab → fixed ids. Training initializes the trunk from `BAAI/bge-small-en-v1.5` (spec §7, 30,522 WordPiece, MIT) — that swap is TASK-13/TASK-15's concern. Unit tests stand alone. The stand-in's ids are all < 30,522, so they remain valid embedding-table indices when the trunk is wired up. **RAPPORT claims no MTEB/embedding-quality property for this tokenizer.**
2. **Specials are added tokens, atomically split before any other splitting** (`_SPECIAL_SPLIT_RE`, longest-marker-first so `</opt>` never fragments to `<opt>`+`/`). An `<opt>` occurrence inside source text IS the marker (standard added-token behavior) — this is what keeps marker boundaries unambiguous at encode time. FR-TOK-01 test asserts the exact marker sequence `["<task>", "<goal>", "<state>", "<opt>", "</opt>", "<opt>", "</opt>"]` and byte-exact `decode(encode(CANONICAL_SEQUENCE)) == CANONICAL_SEQUENCE`.
3. **Joint sequence layout** (spec §5): `<task>{task_family}<goal>{goal}<state>{state}<opt>{o1}</opt><opt>…</opt>`. **No `</state>`** — the five specials are the complete marker set; state runs until the first `<opt>`. (The spec's `…</state>` in the format block is illustrative; adding a sixth marker was rejected to keep the FR-TOK-01 marker set exactly as contracted.)
4. **Budget/truncation:** state is truncated **from the end**; goal prefix and option suffix (all `<opt>…</opt>` pairs, order preserved) stay intact. Documented fallbacks, in order: (a) state → empty, **goal truncated from the end**; (b) if the option block alone exceeds the budget, the option block is truncated from the end (trailing markers may be lost) — pathological, flagged like any other truncation. `len(input_ids) <= budget` is guaranteed on every path (final hard cap).
5. **Flag on a copy:** `encode_example` returns `EncodedExample(example=<frozen DecisionExample>, input_ids, attention_mask, truncated, source, truncation_policy)`. The TASK-03 frozen record is never mutated (`hasattr(example, 'truncated') is False` asserted).
6. **Per-source truncation counting:** module-level `TRUNCATION_COUNTS: dict[str,int]`, `truncation_counts()` returns a copy, `reset_truncation_counts()` clears (tests use it for isolation). When `manifest=` (a mutable mapping) is passed, the counter snapshot is written to `manifest["truncations_per_source"]` and `manifest["truncation_policy"]`. **The run-manifest writer is `src/config/manifest.py` (TASK-01), which this task does not own — the orchestrator or TASK-15 must either pass the live manifest mapping through `encode_example(..., manifest=...)` or merge `truncation_counts()` and `TRUNCATION_POLICY` in at manifest-build time. Key names: `truncations_per_source`, `truncation_policy`.** Untruncated calls still set `truncation_policy` via `setdefault`.
7. **Bucketing:** `bucket_examples(examples, budget=512, batch_size=32, bucket_widths=None)` — widths default to `budget//4, budget//2, budget` = **128/256/512** at 512; exactly three distinct padded lengths max; >3 widths are refused (`TOK_BUDGET_INVALID`). **Right-pad** with `[PAD]` to the bucket width, `attention_mask=0` beyond real length, no `1` after a `0` (asserted per row). Order: buckets short→medium→long, input order preserved within a bucket; last partial batch may be < `batch_size` (never dropped); batches are deterministic across calls. Each `BucketedBatch` records `padding_policy` and `truncation_policy` verbatim (FR-TOK-02's "recorded per batch"). Pre-encoded `EncodedExample` inputs are accepted without counter side effects; plain `DecisionExample` inputs are encoded (and counted) as usual.
8. **Whitespace canonicalization:** one `Ġ` per whitespace char, all-spaces in decoded output (`a\nb` → `a b` in round-trip); single-space-run text round-trips byte-exact (`a  b` → `a  b`). Anything outside printed ASCII decomposes to `[UNK]` (WordPiece convention) — fine because the data pipeline NFC-normalizes and collapses whitespace before encoding.
